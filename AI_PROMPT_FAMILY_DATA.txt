# NameChart Project Overview

## Project Structure

The NameChart project is a Django-based application for visualizing family trees from GEDCOM files. The project consists of several apps, each with specific responsibilities:

1. **core**: Contains base templates, components, and utilities.
2. **upload**: Handles file uploads and initial processing.
3. **browse**: Provides views for browsing individuals and their details.
4. **hud**: Implements the interactive HUD interface for family tree visualization.
5. **charts**: Generates family tree charts.
6. **users**: Manages user profiles and authentication.
7. **generator**: Handles GEDCOM file parsing and data processing.
8. **selector**: Provides views for selecting individuals from GEDCOM files.
9. **parser**: Contains models and utilities for parsing GEDCOM files.

## Key Components

### 1. PersonData Model

The `PersonData` model is a dataclass that represents an individual in a family tree. It contains the following fields:

- `id`: Unique identifier for the individual.
- `full_name`: Full name of the individual.
- `given_name`: Given name of the individual.
- `surname`: Surname of the individual.
- `birth_date`: Birth date of the individual.
- `birth_place`: Birth place of the individual.
- `death_date`: Death date of the individual.
- `death_place`: Death place of the individual.
- `father`: Reference to the father's ID.
- `mother`: Reference to the mother's ID.
- `spouse`: List of spouse IDs.
- `children`: List of child IDs.
- `siblings`: List of sibling IDs.
- `adoptive_parents`: List of adoptive parent IDs.
- `foster_parents`: List of foster parent IDs.
- `step_parents`: List of step-parent IDs.
- `step_siblings`: List of step-sibling IDs.
- `spouses_children`: Dictionary to store children for each spouse.
- `birth_flag`: Binary image data for birthplace flag.
- `death_flag`: Binary image data for deathplace flag.
- `events`: List of events associated with the individual.
- `sex`: Gender of the individual.
- `title`: Professional or nobility titles.
- `occupation`: Occupation or trade.

### 2. GEDCOM Parsing Logic

The `parse_gedcom_data` function in `apps/parser/utils/gedcom_parser.py` is responsible for parsing GEDCOM files and returning structured family tree information. It performs the following steps:

#### First Pass: Collect Individual Data
- Iterates through all individual records in the GEDCOM file.
- Extracts name, sex, title, occupation, and event information.
- Creates a `PersonData` object for each individual.
- Stores individuals in a dictionary with their IDs as keys.

#### Second Pass: Collect Family Data and Establish Relationships
- Iterates through all family records in the GEDCOM file.
- Extracts husband, wife, and children information.
- Links individuals to their families and establishes relationships.
- Populates the `spouses_children` dictionary to store children for each spouse.

#### Identify Root Individuals
- Identifies individuals without parents as root individuals.
- Stores root individual IDs in a list.

#### Identify Siblings
- Identifies siblings for each individual by finding all children in the same family.
- Stores sibling IDs in a list.

#### Identify Adoptive, Foster, and Step Parents
- Identifies adoptive, foster, and step parents for each individual.
- Stores adoptive, foster, and step parent IDs in lists.

### 3. Family Information Display Logic

The `family_info.html` template displays family information in a structured manner. It includes the following sections:

#### Parents Section
- Displays father and mother information.
- Includes adoptive, foster, and step parents.
- Nested under the "Parents" section.

#### Siblings Section
- Displays siblings and step-siblings.
- Nested under the "Parents" section.
- Only displayed if there are siblings or step-siblings.

#### Spouses Section
- Displays spouse information.
- Includes marriage date and place.
- Nested under the "Spouses" section.

#### Children Section
- Displays children for each spouse.
- Nested under the "Spouses" section.
- Only displayed if there are children for the spouse.

#### Children (Main View) Section
- Displays children that are not associated with any spouse.
- Only displayed if there are children not associated with any spouse.

### 4. Custom Template Filters

The project includes custom template filters for handling lists and dictionaries in Django templates:

#### get_item Filter
- Retrieves an item from a dictionary.
- Usage: `{{ dictionary|get_item:key }}`

#### append Filter
- Appends an item to a list.
- Usage: `{{ list|append:item }}`

#### empty_list Tag
- Creates an empty list.
- Usage: `{% empty_list as list_name %}`

### 5. Views and URLs

The project includes several views for browsing and visualizing family trees:

#### browse_individuals View
- Displays a list of all individuals in the GEDCOM file.
- Handles the `file_id` parameter to set the current GEDCOM file in the session.
- Includes the file name in the context for display.

#### individual_detail View
- Displays detailed information for a specific individual.
- Includes family information, such as parents, siblings, spouses, and children.
- Uses the `family_info.html` template to display family information.

#### display_tree_hud View
- Displays the interactive HUD interface for family tree visualization.
- Handles the `file_id` and `individual_id` parameters to set the current GEDCOM file and individual in the session.

#### generate_chart View
- Generates a family tree chart.
- Uses the `image_4generator` module to generate the chart.
- Returns the generated chart as a PDF file.

#### select_individual View
- Allows users to select an individual from the GEDCOM file.
- Displays a list of all individuals in the GEDCOM file.
- Handles the `file_id` parameter to set the current GEDCOM file in the session.
